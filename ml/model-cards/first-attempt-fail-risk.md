## Purpose
Order and staff commissioning work: for each applicable test of a room, a score for the chance that its **first** execution fails, so that a
commissioning engineer can schedule likely failures early and bring the right specialist. The intended commercial use is prioritisation,
never a decision: a score never records, skips, passes or waives a test.

## Target variable
`failed_first_attempt` — 1 if the first recorded result of an applicable test in a room is FAIL. In production the platform produces this
label as a by-product of its evidence ledger (`app.test_result` with `supersedes IS NULL`), which is the data strategy: no external data
purchase, every label backed by stored evidence and an independent verification trail.

## Dataset (synthetic)
`ml/datasets/generate_synthetic.mjs` (seed 20261026) → 1,500 synthetic rooms, 116,062 rows; metadata and SHA-256 in
`synthetic_first_attempt_v1.meta.json` (the CSV is regenerated byte-for-byte by the script; it is not committed).
* **Features are real engine output**: each room is analysed by `@empathia/commissioning-engine` (2.5.4-port.1); every applicable test
  becomes a row with its domain, phase, tier and instrument flag, plus the room's device count, family count, occupancy and room size.
* **Labels are synthetic**, drawn from the declared function `truth()` in the generator plus Gaussian noise (σ = 0.3 on the logit).
  They describe no real room, installer, product or manufacturer.

## Features
Phase ≥ 3, tier 1, instrument-measured, device count, family count, large room, new installation, log occupancy, one-hot test domain
(17 known domains + OTHER). The vocabulary is fixed in code so the JSON model needs no pickle.

## Training and reproducibility
Split by room (`GroupShuffleSplit`, 25 % of rooms held out, seed 7). Standardised features, L2 logistic regression (C = 1); the scaler is
folded into the exported weights. Re-running training reproduces identical weights (test `test_training_is_deterministic`).

## Evaluation (held-out synthetic rooms) — `ml/evaluation/results/REPORT_v1.md`
| Model | ROC AUC | Brier |
|---|---|---|
| constant base rate | 0.500 | 0.167 |
| hand rule (tier 1 + instrument + audio/video) | 0.559 | 0.166 |
| **logistic regression** | **0.609** | **0.163** |
| gradient boosting | 0.606 | 0.163 |
| oracle (the generator's true probability) | 0.637 | 0.160 |

The model approaches the oracle and recovers the declared weights (instrument 0.601 vs 0.6; tier 1 0.467 vs 0.5; phase ≥ 3 0.343 vs 0.35).
**This validates the pipeline, not a prediction about real rooms.** The modest AUC ceiling is a property of the synthetic noise level.

## Limitations and safety
* No real data, so no real validity, calibration, fairness or drift analysis is possible yet.
* Confounding in real data is likely (crews, sites, manufacturers, seasons); the real model needs those features and a temporal split.
* The score must never be shown as a probability about a real room, and must never gate, skip or pass a test.
* Retraining on real data needs: a minimum of several hundred commissioned rooms with first-attempt labels, a data-protection review of
  who-recorded-what (person identifiers are personal data even when hashed), and a held-out time period for evaluation.

## Baseline comparison and next step
Replace the synthetic generator with an extract of `app.test_result` first attempts, keep the same features and evaluation script, and
compare against the hand rule. Ship only if it beats the rule on a later time period and the commissioning lead agrees it helps.
