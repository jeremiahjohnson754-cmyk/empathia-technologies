# Dependency swaps — offline substitutes and their production replacements

The founder's build environment has no package registry. Where the preferred library could not be installed, the starter uses a small
substitute **behind an interface the real library also fits**, so the swap is a contained change. Each row: what is used now, what to use,
the file(s) to change, and the tests that must stay green.

| # | Now (offline substitute) | Production dependency | Change | Guarding tests |
|---|---|---|---|---|
| 1 | Vendored PostgreSQL client: SCRAM/MD5/cleartext auth, TLS, extended protocol, pool (`services/enterprise-api/src/db/pg.ts`, `PgConnection` :71, `PgPool` :237, `configFromUrl` :274) | `pg` (node-postgres) + `pg-pool` | Implement `Queryable` (`query(text, params) → { rows, rowCount }`) over `pg`; keep `tx()` setting `app.tenant_id`/`app.user_id` with `set_config(…, true)` (`pg.ts:261`); keep the `JsonParam`/`asJson` behaviour for jsonb parameters | all of `tests/integration`, `tests/security/authz.test.mjs` (RLS cases), backup drill |

Rule for every swap: the guarding tests are not edited to make the new dependency pass, except where a test mints tokens or starts a
server through the substituted API — then only that setup code changes, and the expectations stay identical.
