# Empathia v1.8: Implementation Sequence / Measurable Outcomes

## Stage 0 — Current-source truth and no-loss mapping
- Verify current Git HEAD, Render deployments, all affected website routes, backend/DB migrations, payment system in sandbox, media files and connector registry.
- Byte-compare existing v1.7 rows and original SIGNAL/campus sources; keep existing 90 rooms and 52 role IDs.
- Baseline first-use, Web Vitals, QR-to-passport, search latency and pilot outcomes; mark any unobserved metric NOT_RUN.

## Stage 1 — Proof Center vertical slice
- Schema, approved public projection, evidence source link, proof status state machine, expiration and revocation.
- Display one synthetic (honestly labeled) commissioning claim consistently on both websites.
- Negative-test public proof access to private evidence, stale live label, unsupported vendor feature and unapproved claim publication.

## Stage 2 — Guided four-world entry
- Four worlds, each 4–6 clear purpose cards, one immediate synthetic task per world; advanced retains original 52 roles.
- Support direct routes, keyboard/screen readers, mobile and cross-world switch with no leakage.
- Compare completion time and user understanding against baseline; do not assume improved UX just because fewer cards appear.

## Stage 3 — Pilot storefront and source readiness
- Keep original prices and checkout semantics. Ship supported/not-supported selector and ready-after-approval explanations.
- Provider-hosted sandbox payment, verified webhook, idempotent entitlement, authorized source preflight, bounded 3–5 room demo/live observation.
- Customer admin consent and connector capability matrix must be in place; never test on unapproved employer devices.

## Stage 4 — Performance/resilience and real engineering proof
- Defer non-selected 3D worlds and nonessential video, retain 2D route and field workflows.
- Durable report generation, QR and search metrics, cache isolation, offline/slow tests, documented SLO candidates.
- Verify one actual source-to-report engineering workflow or clearly bounded lab simulation, including artifacts from same report snapshot.

## Stage 5 — Film 13 and marketing integration
- Storyboard+provenance, 20–30s technically plausible scene, AV engineer/media director/human QC; record corrections.
- Authorize/create full master only after pilot accepted and asset/rights/claims correct.
- Put one film CTA in the corporate conversion journey and one corresponding proof-linked investor tour; no media placeholders disguised as final.

## Stage 6 — Adversarial QA / release authorization
- Extend v1.7's eighteen reviewer perspectives with new v1.8 tests. Every P0 with source evidence or clearly blocked.
- Conduct negative-auth, billing duplicate, QR identity, false-proof, tenant switch, connector outage, video uncanny, and mobile bandwidth runs.
- Release candidate packet: commit SHA, requirements/test coverage, evidence pointers, performance deltas, blocked items, rollback, founder signoff and customer approvals.

### Definition of a completed workstream
**Code exists + reproducible tests run + test evidence preserved + UX verified on representative devices + updated provenance/permissions + defects closed + required reviewer approved.** A documentation paragraph or AI-generated screenshot alone is not completion.
